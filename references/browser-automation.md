# 浏览器自动化实战（GitHub 建仓与设备码授权）

本文件记录**实测有效**的浏览器操作细节。多数平台没有公开的自动化接口，
真正的"最后一公里"往往要在浏览器里点——而点的方式有坑。

## 一、用谁浏览：内置浏览器 vs 用户自己的浏览器

| | WorkBuddy 内置浏览器（IAB） | 用户自己的 Chrome（扩展模式） |
|---|---|---|
| 登录态 | 无，需重新登录 | **沿用用户已登录的会话** |
| 能做的事 | 公开页面、需登录的会被挡 | 已登录的一切（GitHub、Gmail、公众号后台…） |
| 标签页模型 | 仅本会话 | 可接管用户已打开的页 |

**要操作需要登录的站点（GitHub、公众号后台），必须用用户自己的 Chrome。**
`browsers_list` 会返回两个实例：`type: "desktop"` 是内置浏览器，
`type: "extension"` 且 capabilities 含 `user_tabs` 的是用户浏览器。

## 二、设备码授权页面的四个坑

GitHub 的 `/login/device` 流程有三个页面，实测细节：

### 坑 1：账号选择页的 Continue 按钮点不动

访问 `/login/device` 会跳到 `/login/device/select_account`，
该页的 "Continue as xxx" 按钮**用 DOM 点击和坐标点击都可能不触发跳转**。

**解法**：直接用带参数的网址跳过账号选择器：

```
https://github.com/login/device?skip_account_picker=true
```

### 坑 2：验证码是分格输入框，整段粘贴无效

页面是 8 个单字符 input（`user-code-0`…`user-code-8`，中间没有 4 号因为那是连字符位）。

| 方式 | 结果 |
|---|---|
| 整段 `type`（含 `insertText`） | ❌ 只落地第一个字符 |
| 剪贴板粘贴（Cmd+V） | ❌ 无效 |
| `dom_cua_type` | ❌ 无效 |
| **`cua_type` 逐字（每次一个字符）** | ✅ 有效，且自动跳到下一格 |

连字符不用输——8 个字符填完即可，页面会自动跳过连字符位。

### 坑 3：第一个输入框要用坐标点击聚焦

DOM 点击那个 input **不会**产生焦点，敲键盘没反应。
必须用**坐标点击**（先截图拿坐标）把焦点打进去。

### 坑 4：确认页是 POST-only，刷新会 404

`/login/device/confirmation` 页面**不能刷新**（刷新后 GET 该 URL → "Page not found"）。
要把验证码输错重试，只能回到 `/login/device` 重新走一遍。

### 授权按钮有解禁延迟

确认页的 Authorize 按钮初始是 `disabled`，需要等页面自己的计时器解禁。
如果标签页在后台，Chrome 的定时器节流会让它迟迟不解禁——**把标签页切到前台**再等。

## 三、读 6 位验证码的实用做法

GitHub 的 sudo mode 验证邮件会发到**账号的主邮箱**（备用邮箱在
Settings → Emails 里能看到，且"Allow all verified emails"时两个都收）。

如果用户 Chrome 里已经登录了邮箱（很常见），可以直接在浏览器里打开邮箱读验证码，
**不用让用户去翻邮件**。实操路径：

1. 打开 `https://mail.google.com/`（或用户实际在用的邮箱）
2. 用搜索框搜 `GitHub` / `verification code`
3. 从邮件列表行的预览文本里直接读出 6 位数字
4. 填进 GitHub 的验证码框

> ⚠️ 只看这一封验证码邮件，不翻其他邮件；读完不要把邮箱内容写进任何产物。

## 四、从页面拿到一次性密钥（PAT）

创建 token 后，页面上会显示一次明文，只显示这一次。

**取它的可靠方式**：

1. 找到 "Copy token" 的复制图标（`<clipboard-copy>` 元素）
2. **用坐标点击**图标（DOM 点击不写系统剪贴板，坐标点击才写）
3. 立即 `pbpaste` 取出来 → 直接存钥匙串，**不要让明文进入对话记录或文件**

坐标取法：先截图，复制图标在密码框右侧（一般 x ≈ 页面中线偏右，y ≈ 密码框同一行）。

## 五、其他实测细节

| 现象 | 原因 / 解法 |
|---|---|
| 截图尺寸在 1440 / 1425 之间跳 | 窗口状态变化导致。**每次坐标点击前重新截图**，别复用旧坐标 |
| `End` / `Home` 键无效 | 页面焦点不在文档上。用 `dom_cua_scroll` 逐屏滚（一次约一屏） |
| 工具参数传数组被改成对象 | 本环境对数组参数有转义问题。优先用单字符串参数（如 `keys: "Meta+V"`） |
| `urlopen(..., headers=...)` 报错 | 必须用 `urllib.request.Request` 对象承载 headers |
| 页面加载超时 ERR_TIMED_OUT | 先用 curl 测同一域名是否可达，区分「站点挂了」和「浏览器抽风」 |

## 六、代理环境下的特别提醒

如果本机走本地代理（Clash/Surge 类，常见监听 `127.0.0.1:1082`，系统代理指向它），
出现「浏览器 ERR_TIMED_OUT / chrome-error://chromewebdata/」时，
**先确认代理进程活着但上游节点通不通**：

```bash
nc -z -w 3 127.0.0.1 1082 && echo "代理在监听" || echo "代理没在服务"
curl -s -o /dev/null -w "%{http_code}\n" --max-time 10 https://api.github.com
```

进程在、端口通、但请求超时 = **上游节点失效**，需要用户在客户端里换节点。
这种情况浏览器怎么点都没用，别浪费轮次。
