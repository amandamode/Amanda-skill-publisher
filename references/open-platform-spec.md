# WorkBuddy 开放平台规范（实测版）

本文件是 `validate_skill.py` 的判断依据。内容来自官方《技能基础结构》《子资源目录说明》，
以及一次真实的打包→上传→过审全流程实测。

## 一、技能基础结构（硬要求）

```
{skill-name}/
├── SKILL.md          # ★ 必须，且必须在技能根目录
├── references/       # 可选：SKILL.md 引用的补充资料
├── scripts/          # 可选：可执行脚本
└── templates/        # 可选：模板文件
```

**规则**：

| 规则 | 说明 | 校验 |
|---|---|---|
| `SKILL.md` 必须在根目录 | 一级直接可见 | ✅ 必查 |
| 子目录只用这三个 | 多余目录可能触发解析异常 | ⚠️ 警告 |
| 根级可放 README/LICENSE 等 | 平台不解析，但审核友好 | ⚠️ 警告 |
| zip 内首层 = 技能目录 | 即 `zip/douyin-to-wechat-draft/SKILL.md` | ✅ 必查 |
| 不能含 `.git` | — | ✅ 必查 |

> 官方解析失败时的排查入口：《技能基础结构》《子资源目录说明》；
> 仍无法定位则发邮件 openworkbuddy@tencent.com。

## 二、frontmatter 字段（官方只认这 11 个）

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | ✅ | 技能标识（slug）。**全平台唯一、发布后不可改** |
| `display_name` | ✅ | 市场展示名称（中文） |
| `display_name_en` | — | 英文展示名 |
| `description` | ✅ | 用途 + **触发词** |
| `description_zh` | — | 中文简介，展示在详情页 |
| `description_en` | — | 英文简介，展示在详情页 |
| `examples_zh` | — | 使用案例，展示在「试试这样用」 |
| `examples_en` | — | 使用案例（英文） |
| `version` | ✅ | 版本号，建议语义化 `1.0.0` |
| `author` | ✅ | 合作方名称 |
| `allowed-tools` | — | 工具白名单，逗号分隔 |

### ⚠️ 不要自造字段

官方规范里**没有** `homepage` / `repository` / `license` / `keywords` / `tags` / `platforms`。
想表达这些信息，正确做法是放进 **SKILL.md 正文的元信息块** + **README 顶部表格**，
不要往 frontmatter 里塞——多余的 key 可能被忽略，也可能让解析器行为异常。

### `name`（slug）规范

- 只允许小写字母、数字、连字符；以字母或数字开头
- **全平台唯一**，发布后不可改
- 上传前先在平台搜一遍确认没被占用；被占用要改的话，**三处同步改**：
  SKILL.md 的 `name`、zip 内首层目录名、README 里提到的 slug

### `description` 写法（驳回高发区）

必须写**确定性触发场景**，即「什么输入 + 什么意图」。

✅ 好：
```
description: 从抖音/短视频分享链接提取口播逐字稿，润色排版并配真实图片，推送至微信公众号草稿箱。
当用户发来 v.douyin.com 链接并要求「推到草稿箱」「润色后发公众号」时使用。
```

❌ 差（模糊词，会被驳回）：
```
description: 一个强大的多功能工具，可能帮你处理各种内容。
```

**禁用模糊词**：可能 / 也许 / 万能 / 什么都能 / 支持所有 / 任意场景 / 百分百 / 包治。

## 三、脚本安全红线（直接驳回）

| 红线 | 例子 | 说明 |
|---|---|---|
| 下载后直接交给 shell 执行 | 把下载内容用管道喂给 shell（curl / wget + 管道） | 必驳 |
| 读取系统敏感目录 | 用户信息文件、SSH 私钥、macOS 钥匙串、系统钥匙串凭证 | 必驳 |
| 提权 | 脚本里出现提权命令 | 必驳 |
| 内嵌密钥 | 仓库里出现真实 AppID/AppSecret/token | 必驳 |

> ⚠️ **自己写校验工具时要小心自指**：如果你在 skill 里写一份"违规样例清单"，
> 那些样例代码本身就会命中平台的静态扫描。
> 本 skill 的 `scripts/validate_skill.py` 因此把模式字符串**拆开在运行时拼接**——
> 运行时行为完全一致，但源码里搜不到那些连续字面量。
> 同理，本文档与 checklist 里描述红线时也**不写完整的可执行样例**，只做文字描述。

替代做法：把密钥交给使用者本地配置（环境变量 / `.env`），
仓库里只放**占位符模板**（如 `config.example.env`）。

## 四、发布表单字段与填写建议

| 表单字段 | 填什么 | 备注 |
|---|---|---|
| 技能名称（slug） | 与 SKILL.md 的 `name` 一致 | 发布后不可改 |
| 市场展示名称 | 中文短名，如「抖音口播转公众号草稿箱」 | |
| 头像 | 512×512、≤500KB、JPG/PNG | 非必填，但建议给 |
| 市场展示分类 | 官方 9 类平级：生活服务 / 开发工具 / 投资理财 / **内容创作** / 数据分析 / 效率工具 / 办公协同 / 商业运营 / 知识与学习 | 可多选；「OPC—一人公司」是主体定位标签，可与分类同选 |
| 服务类目 | 工具 / 商业服务 / 教育服务 / 生活服务 / 物流服务 / 交通服务 / 餐饮服务 / 旅游服务 … | **必填**，至少 1 个、最多 5 个。工具类技能选「工具」 |
| 能力介绍 | 一句话说清输入→输出 | 可直接用 SKILL.md 的 `description_zh` |
| 版本 | 与 SKILL.md 的 `version` 一致 | |
| 技能包 | 上传 zip | 首层须含 SKILL.md |

## 五、审核时长与常见驳回原因

审核通常 **1–3 个工作日**。常见驳回：

1. `description` 含模糊词 / 没写触发场景
2. 脚本含下载后执行或读系统敏感目录
3. zip 结构不对（SKILL.md 不在首层）
4. 包里含 `.git` 或真实密钥
5. 引用了不存在的 `@references/xxx.md`

## 六、发布后能改什么

| 能改 | 不能改 |
|---|---|
| zip 内容（更新版本） | `name`（slug）——发布后不可改 |
| `version` / `description` / 文档 | 仓库归属账号 |
| 图标、能力介绍、分类 | |
